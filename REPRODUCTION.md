# Reproduction Guide

Written for someone starting from a clean environment who has never seen this
project.

There are two paths:

| Path | Needs | Cost | What it proves |
|---|---|---|---|
| **Verification** | Docker only | $0.00 | Every number in the results table, recomputed from committed predictions |
| **Live agent run** | Docker + Claude Code on a paid plan | ~$1–4 | That the committed predictions were genuinely produced by the agent |

Start with verification. It requires no API key, no subscription, and no
network access beyond the initial Docker image pull.

| Item | Version used | Notes |

No credentials are contained in this submission. `.env` is not used and no API
key is required for the verification path.

## 2. Verification path (no cost)

```bash
git clone <repo-url>
cd fec-2026-drift-detector
bash run.sh verify
```

Expected output:

```
== building image ==
== regenerating corpus (deterministic) ==
csv sha256: 931dfa2524951ebb
schema-invisible defects: 10/15

== expected S csv sha256: 931dfa2524951ebb ==

== re-scoring every committed prediction set ==
  [schema_baseline]   primary_score   0.419
  [prompt_baseline]   primary_score   0.925
  [agent_S]           primary_score   0.775
  [agentv2_S]         primary_score   0.944
  [agentv2_L]         primary_score   0.963
```

Runtime: about 90 seconds, most of it the Docker image build.

This regenerates the evaluation corpus from a fixed seed, prints its hash so
you can confirm it matches the data the results were produced on, then
re-scores every committed prediction file against ground truth.

## 3. Corpus hashes

The corpus is generated deterministically. Hashes are over CSV bytes only, so
they are stable against metadata changes.

| Tier | Rows/file | Corpus size | CSV sha256 (first 16) |
|---|---|---|---|
| S | 200 | 0.5 MB | `931dfa2524951ebb` |
| M | 5,000 | ~13 MB | regenerate to verify |
| L | 50,000 | 131.2 MB | `fec769798426786d` |

Only the S tier is committed. M and L are regenerated on demand:

```bash
docker run --rm -v "$PWD://app" -w //app drift python eval/gen_cases.py --scale M
docker run --rm -v "$PWD://app" -w //app drift python eval/gen_cases.py --scale L
```

L takes about 12 seconds to generate.

## 4. Live agent run (costs money)

Requires Claude Code authenticated on a paid plan.

```bash
./run.sh agent-v2 S      # 16 cases, ~20k tokens each, ~$1.00
./run.sh agent-v2 L      # 16 cases at 50k rows, ~20k tokens each, ~$1.05
./run.sh agent-v1 S      # profiling only, no invariant checking
./run.sh baseline-schema # deterministic, free
```

Runners skip any case that already has a committed prediction. To force a
re-run, delete the relevant file under `preds/<label>/`.

The prompt baseline is not exposed through `run.sh` because at L tier it is
rejected by the API; the failure is captured in
`results/evidence/baseline_L_attempt.json`.

## 6. What the data is

Fully synthetic. Generated by `eval/gen_cases.py` from a fixed seed. No real
customer data, no scraped data, no third-party datasets. Names are drawn from
a hardcoded list and email addresses use the reserved `example.com` domain.

Each case is a pair of daily feed files plus ground truth:

```
eval/cases/07_unit_change_currency/
  day1.csv     reference feed
  day2.csv     next-day feed with an injected defect
  truth.json   ground truth: defect type, affected columns, severity
```

16 cases: 14 with defects, 2 clean controls. The controls measure false
positives — without them, a system that flags everything would score
perfectly on recall.

## 7. Verifying the raw API responses

Every agent run's unedited API response is committed under `_raw/`. These
contain token counts, costs, timings and the model's structured output, so the
results table can be audited without re-running anything:

```bash
python -c "
import json,glob
for f in sorted(glob.glob('_raw/agentv2_S_*.json')):
    d=json.load(open(f,encoding='utf-8')); u=d['usage']
    tot=u['cache_creation_input_tokens']+u['cache_read_input_tokens']+u['input_tokens']
    print(f.split('_S_')[1][:-5], tot, 'tokens', round(d['total_cost_usd'],3))
"
```

## 8. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `failed to connect to the docker API` | Docker Desktop not running | Start Docker Desktop, wait for "Engine running" |
| `no such file or directory /app/eval/...` | Bind mount did not resolve | Run `run.sh` from the repo root, not from a parent directory |
| `Prompt is too long` on a baseline run | Expected at L tier | This is the documented result, not a bug |
| Hash mismatch after clone | Git rewrote line endings | `eval/cases/** -text` in `.gitattributes` prevents this; confirm it is present |

## 9. Determinism and limitations

**Deterministic:** corpus generation (fixed seed), the schema baseline, the
profiler, the invariant checker (fixed sampling seed), and scoring. Running
`run.sh verify` twice produces byte-identical output.

**Not deterministic:** the agent runs. They call a language model, so a live
re-run will not reproduce the committed predictions exactly. Expect the
primary score to land within a few points of the reported value rather than
matching it precisely. The committed predictions and their raw API responses
are the record of what was actually measured.

**Platform:** developed and tested on Windows 11 with Git Bash and Docker
Desktop (WSL2 backend). `run.sh` branches on `uname` to handle the difference
between Windows and POSIX bind-mount paths. The POSIX branch is standard but
has **not** been executed on Linux or macOS, so it is untested rather than
verified.

**Scoring:** `localization_exact_pct` and `classification_pct` are computed
only over correctly detected cases. They must be read alongside recall — a
system that detects little can still show high localization on the few cases
it catches. See the README for three cases where ground-truth
`affected_columns` is arguably ambiguous.
